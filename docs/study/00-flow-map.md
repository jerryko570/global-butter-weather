# 00. 마스터 흐름 지도 — 백엔드 ↔ 프론트엔드 (한 장 요약)

> 매번 헷갈릴 때 여는 커닝페이퍼. 새 코드 볼 때 **"읽기냐 쓰기냐 / 통로 ①이냐 ②냐"** 두 질문만 던지면 위치가 잡힌다.
> 상세는 [[04-join]](데이터흐름·두통로·클라이언트3) · [[05-mutation]](쓰기).

---

## 🗺️ 읽기 vs 쓰기 (대칭으로)

```
                    프론트엔드                          │              백엔드
─────────────────────────────────────────────────────┼──────────────────────────
READ (useQuery)                                        │
컴포넌트                                                │
  └ useProduct(slug)  ← 자동 실행                       │
       └ supabase.from().select().eq()  ── 통로① ──────┼──▶ [RLS 검수] ─▶ DB(읽기)
                                          (훅→DB 직접)   │         │
       {data, error} ◀───────────────────────────────┼─────────┘ (반환)
  React Query 포장 {data, isLoading}                    │
  └ 컴포넌트가 화면에 그림                                │
─────────────────────────────────────────────────────┼──────────────────────────
WRITE (useMutation)                                    │
컴포넌트                                                │
  └ usePurchase()  ← 대기(배선)                         │
  └ (버튼) mutate(데이터)  ← 수동 발사                   │
       └ postPurchase → fetch('/api/...')  ── 통로② ───┼──▶ Route Handler(서버)
                                     (훅→서버→DB)        │       └ service role/RLS ─▶ DB(쓰기)
       {data, error} ◀───────────────────────────────┼─────────┘ (반환)
  React Query {mutate, isPending}                      │
  └ onSuccess(반환값) → 다음 동작 (결제창 등)            │
```

---

## 🔑 핵심 대칭

| | 읽기 (useQuery) | 쓰기 (useMutation) |
| --- | --- | --- |
| 실행 | **자동** (마운트) | **수동** (mutate) |
| 함수 | `queryFn` | `mutationFn` |
| 통로 | **①** 훅→DB 직접 | **②** 훅→서버(Route Handler)→DB |
| 꾸러미 | `data, isLoading` | `mutate, isPending` |
| 성공 후 | 화면 렌더 | `onSuccess` 콜백 |

---

## 🚪 두 통로 (여기가 핵심)

```
통로①  브라우저 → supabase-js → DB      (읽기·간단쓰기, RLS가 지킴)
통로②  브라우저 → 내 서버(app/api) → DB  (시크릿 필요: 결제·service role·웹훅)
```
→ **"비밀키가 필요하냐?"** 로 갈린다. 안 필요 = ①(훅 직접), 필요 = ②(서버 경유).

---

## ⚡ 어디서든 안 변하는 3원칙

1. **요청을 보낸다 → DB가 데이터를 돌려준다** (내가 데이터를 보내는 게 아님)
2. **DB 앞엔 항상 RLS 문지기** (service role만 우회)
3. **React Query가 상태(data/error/loading)를 포장 + 캐시** — 컴포넌트는 그걸 꺼내 씀

---

## 🎯 한 줄

**컴포넌트 → 훅(자동=읽기 / 수동=쓰기) → 통로①(직접) 또는 ②(서버) → RLS → DB → `{data,error}` → React Query 포장 → 컴포넌트. 읽기·쓰기는 이 뼈대의 두 변주일 뿐.**

---

## 🧭 새 코드 만날 때 던지는 2질문
1. **읽기냐 쓰기냐?** → useQuery(자동) / useMutation(수동)
2. **통로 ①이냐 ②냐?** → supabase 직접 / fetch로 서버 경유 (비밀키 유무)
