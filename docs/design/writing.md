# 문구 — 손님에게 하는 말

> [tokens.md](tokens.md) 가 색과 크기의 규약이라면, 이 문서는 **말의 규약**이다.
> 브랜드의 목소리를 정하는 것은 이나래이고, 여기는 **매번 묻지 않아도 되도록 경계를 적어두는 곳**이다.

## 0. 왜 — 먼저 재봤다

지금 손님이 보는 말은 **293줄 · 26개 파일**에 흩어져 있다. 대부분 개발하면서 적은 것이다.

| 무엇        | 지금                                                                  |
| ----------- | --------------------------------------------------------------------- |
| 영문 라벨   | 서로 다른 것 16종 (`Total` `SHOP` `Sold Out` `Our Story` …)           |
| 실패 문구   | **스무 군데쯤이 「…하지 못했습니다」로 끝난다** — 뭘 해야 하는지 없다 |
| 말투        | 「담긴 것이 없습니다」와 「최근에 주문하신 상품이…」가 한 화면에 있다 |
| 버튼과 안내 | 같은 말을 두 번 한다 (2026-09-30에 세 군데 걷어냈다)                  |

## 1. 화면의 말은 그 화면의 언어를 따른다 ★

**영문으로 남는 것은 고유한 이름뿐이다.** 그 밖의 모든 말 — 버튼 · 안내 · 오류 · 구획 이름 · 상태 · 수치 — 은 **한국어 화면이면 한국어, 영어 화면이면 영어**다.

| 영문으로 남는 것 | 예               |
| ---------------- | ---------------- |
| 워드마크         | `BUTTER WEATHER` |
| 언어 토글        | `KR` · `EN`      |
| 고유명사         | `Instagram`      |

그 밖에는 없다.

### 처음에는 다르게 적었다 — 뒤집힌 기록 (2026-09-30)

이 문서의 첫 판은 **「작은 대문자 라벨은 영문 조형이라 번역하지 않는다」**였다. 근거는 `uppercase` 가 라틴 문자에만 걸린다는 것이었고, 그 자체는 사실이다.

**그런데 화면에서 실제로 일어난 일은 달랐다.**

```
상품        ₩11,900     ← 한국어
배송비       ₩3,500      ← 한국어
Total       ₩15,400     ← 영문 하나만
```

같은 블록 세 줄 중 하나만 영문이었고, 이것이 **장바구니 · 주문서 · 주문 상세 세 화면에서 반복**됐다. 헤더에도 「주문 내역 · 로그아웃」 옆에 `CART` 가 있었다. 상품 칸은 `KEYRING` 인데 Sidebar 는 「키링」이었다 — **같은 것을 두 이름으로 부르고 있었다.**

「조형이냐 말이냐」로 가르면 **판정이 매번 필요하고, 그 판정이 사람마다 달라서 결국 섞인다.** 이나래가 한국어로 정했다 (2026-09-30).

> **`uppercase` 클래스는 지우지 않는다.** 한글에는 효과가 없지만 죽은 값이 아니다 — EN 이 열리면 같은 자리에 영문이 들어오고 그때 필요하다.

### 남겨둔 것 — 이나래가 볼 자리

첫 화면의 `Lookbook` · `Our Story` 는 **구획 이름이라기보다 편집의 말**이라 손대지 않았다. 태그라인(「작은 오브제, 정직한 디자인.」)과 같은 층이다.

| 전                            | 후                   | 어디                                 |
| ----------------------------- | -------------------- | ------------------------------------ |
| `Add to Cart`                 | 장바구니 담기        | 상세                                 |

| `Not Found`                   | 찾을 수 없음         | 404                                  |

## 3. 버튼은 한국어다 — 정해졌다 (2026-09-30)

`Add to Cart` · `Buy It Now` · `Sold Out` 이 마지막까지 남았던 자리다. **기준대로 한국어로 간다** — 버튼은 「말」이고, 말은 언어를 따라간다.

| 전            | 후                |
| ------------- | ----------------- |
| `Add to Cart` | **장바구니 담기** |
| `Buy It Now`  | **바로 구매**     |
| `Sold Out`    | **품절**          |

**기준에 예외를 두지 않은 것이 이 결정의 값어치다.** 여기서 한 번 봐주면 다음 예외가 쉬워지고, 그러면 규약이 아니라 목록이 된다.

대신 **대문자 조형은 그 버튼에서 포기한다.** 얻는 것은 EN 버전과 실제로 갈린다는 것이다 — 영문 버튼만 남겨두면 **두 언어의 화면이 같아진다.**

> **`uppercase` 클래스는 지우지 않는다.** 한글에는 효과가 없지만 죽은 값이 아니다 — EN 이 열리면 같은 자리에 영문이 들어오고 그때 필요하다.

## 4. 실패했을 때 — 무엇을 해야 하는지 말한다 ★

지금 실패 문구는 대부분 **일어난 일만** 말한다.

```
❌  주문을 완료하지 못했습니다.
❌  결제를 준비하지 못했습니다.
❌  주문하지 못했습니다. 잠시 뒤 다시 시도해 주세요.
```

**손님이 다음에 무엇을 해야 하는지가 없다.** 「잠시 뒤 다시」는 그것을 말한 척하는 문장이다 — 정말로 기다리면 되는 경우에만 쓴다.

### 담을 것 둘

1. **무엇이 막혔나** — 한 문장
2. **이제 무엇을 하면 되나** — 할 수 있는 일이 있을 때만

```
✅  브릭가든 이(가) 방금 품절됐습니다. 결제를 취소했습니다.
✅  주문을 완료하지 못했습니다. 결제는 그대로 있습니다 — 주문 내역에서 다시 확인해 주세요.
```

**설명을 늘려 풀지 않는다** (CLAUDE.md 표현 원칙). 두 문장을 넘기면 대개 화면이 잘못된 것이다.

### 손님 탓으로 들리게 쓰지 않는다

```
❌  잘못 입력하셨습니다
✅  받는 분·연락처·주소를 채워 주세요
```

## 5. 말투 — 하나로

- **「…습니다」로 끝낸다.** 「…해요」를 섞지 않는다
- **높임은 손님의 행동에만.** 「주문하신 상품」은 맞고, 「담긴 것이 없습니다」도 맞다 — 물건은 높이지 않는다
- **「고객님」을 쓰지 않는다.** 부르지 않아도 문장이 성립한다

## 6. 버튼

- **동사로 끝낸다** — 「주문하기」 「결제하기」 「빼기」
- **버튼이 한 말을 아래에서 또 하지 않는다.** 2026-09-30에 「결제는 아직 준비 중입니다」류 셋을 걷어낸 것이 그 예다
- **진행 중에도 같은 말을 쓴다** — 「결제하기」 → 「결제를 여는 중…」. 다른 단어로 바꾸면 다른 버튼처럼 보인다

## 7. 언어가 둘이 될 것을 염두에 둔 제약 ★

지금은 KR 하나지만 Sidebar 에 `KR · EN` 자리가 이미 있다. **나중에 고생하지 않으려면 지금 지킬 것이 셋이다.**

**① 문장을 조각내 이어붙이지 않는다.**

```
❌  {name} + ' 은(는) 품절됐습니다'      ← 영어는 어순이 다르다
✅  `${name} 이(가) 품절됐습니다`        ← 문장 하나가 통째로 번역 단위
```

**② 숫자·이름은 자리표시자로 끼운다.** 문장을 잘라 앞뒤로 붙이지 않는다.

**③ 조형 라벨은 번역 대상이 아니다.** 1절의 그 목록은 언어가 바뀌어도 그대로다. **번역 파일에 넣지 않는다** — 넣는 순간 누군가 번역한다.

> 번역을 **지금 넣지는 않는다.** 문자열을 한 군데로 모으는 일은 EN 을 실제로 열기로 할 때 한다. 지금은 **위 셋만 지켜두면** 그때 옮기는 것이 기계적인 일이 된다.
