# 버터웨더 — 로드맵

> **2026-09-05 작성.** 브랜드 정의는 [../brand/foundation.md](../brand/foundation.md)에 있다. 이 문서는 **그것을 무슨 순서로 만드는가**만 다룬다.
>
> **가까운 것은 깊게, 먼 것은 얕게 적는다.** M0은 스토리까지, M1은 에픽까지, M2 이후는 이니셔티브까지만 적었다. 먼 것을 지금 자세히 적으면 어차피 뒤집힌다.

## 계층

| 층                 | 무엇                                       | 크기        |
| ------------------ | ------------------------------------------ | ----------- |
| **마일스톤** `M`   | 무엇이 되면 끝인지로 정의한다. 상태의 변화 | 몇 주~몇 달 |

## 지금 위치 (실측)

**화면이 하나도 없다.** `src/`에 CSS 두 개뿐이고 `layout.tsx`·`page.tsx`가 없다. `next build`는 `/404`만 만든다. Supabase 프로젝트 없음, `.env.local` 없음, Vercel 미연결.

있는 것: 툴링(eslint·prettier·husky·commitlint), PR·Slack 워크플로우, `.gitattributes`·`.prettierignore`, design token, 브랜드 문서.

## 로드맵을 묶는 제약

브랜드 문서에서 그대로 따라 나오는 것들이다. 순서와 설계를 여기서 정한다.

| 제약                              | 출처       | 로드맵에 미치는 영향                                             |
| --------------------------------- | ---------- | ---------------------------------------------------------------- |
| 첫 화면에서 물건을 팔지 않는다    | 5-7 ②      | **랜딩이 카탈로그가 아니다.** M1이 M2보다 앞선다                 |
| 설명 텍스트가 거의 없다           | 4절, 5-7 ③ | 카피가 아니라 **이미지가 콘텐츠**다. 에셋 파이프라인이 초기 과제 |
| 틀은 조용하고 알맹이만 색         | 5-8        | 디자인 시스템의 첫 규칙. M0에서 코드로 굳힌다                    |
| 하루의 시각(6·12·18·24)이 구조 축 | 5-3        | 사이트 IA·카탈로그 시간 축의 **후보**. M4에서 푼다               |
| 국내/해외를 나누지 않는다         | 3절        | 언어·통화·배송을 **데이터 모델에 처음부터** 자리로 둔다          |
| 매체가 미정이다                   | 7절        | 상품 모델이 **특정 카테고리에 종속되면 안 된다**                 |
| maker 개념을 열어둔다             | 9절        | 플랫폼 확장의 값싼 보험. M2에서 컬럼만 만들어 둔다               |
| 인스타·스토어를 이어간다          | 5-2        | 사이트가 유일 채널이 아니다. **채널 간 연결**이 과제로 남는다    |

## 플랫폼의 세 면

> 2026-09-05 확정. 「플랫폼」이 무엇을 뜻하는지 정해졌다.

버터웨더에서 플랫폼은 **마켓플레이스가 아니다.** 세 면을 뜻한다.

| 면            | 무엇                                        | 누가 쓰나                      |
| ------------- | ------------------------------------------- | ------------------------------ |
| **고객향**    | 웹사이트                                    | 사는 사람                      |
| **관리자향**  | 상품·주문·콘텐츠를 다루는 페이지            | 이나래·홍설아                  |
| **외부 채널** | 인스타그램, 스마트스토어, 그 밖의 3rd party | 사는 사람이 **먼저 만나는 곳** |

### 이것이 로드맵에 미치는 영향

**1. 관리자향은 마일스톤이 아니라 모든 마일스톤에 따라붙는 축이다.**

상품을 넣으려면 M2에, 주문을 보려면 M3에 관리자 화면이 필요하다. 맨 뒤에 몰아서 만드는 것이 아니라 **각 마일스톤이 고객향·관리자향 두 면을 함께 갖는다.**

**2. 외부 채널은 부록이 아니라 여정의 출발점이다.**

브랜드 문서 6절은 브랜드 경험을 "외부에서부터 웹사이트에 도착하기까지의 여정 전체"로 정의했고, 5-2절은 인스타·스마트스토어를 이어가기로 정했다. **사이트는 유일한 채널이 아니라 도착지다.** M4가 이것을 다룬다.

**3. 여러 만든 주체(maker)를 담는 구조는 플랫폼의 뜻이 아니었다.**

다만 브랜드 문서 2절(편집 확장)과 9절(maker 개념)이 **별도의 이유로** 그 자리를 열어두라고 했다. 「값싼 보험」에는 남기되 근거를 그쪽으로 옮긴다.

## 열린 결정

로드맵을 더 진행하려면 답이 필요한 것들이다.

1. **첫 화면에 무엇을 두는가** (M1) — 좋아하는 레퍼런스들이 각각 다르게 푼다. karactor는 커튼 사진, colorcolour는 인물, sunlovetour는 컬렉션 성좌. **물건이 아직 없으므로 더 열려 있다.** 이나래 판정 필요
2. ~~**플랫폼이 무엇을 뜻하는가**~~ → **해소됨. 고객향 · 관리자향 · 외부 채널 세 면이다. 「플랫폼의 세 면」 참조.**
3. **매체를 언제 정할 것인가** (M2) — 7절은 지금 정하지 않는 것이 선택이라고 했다. 다만 M2에서 상품을 넣으려면 무언가는 있어야 한다. 기존 비즈 재고로 시작할지 결정 필요
4. **카탈로그의 시간 축** (M4) — 9절 보류 항목. 하루의 시각이 출발점으로 확보됐으니 지금 풀 수 있다
